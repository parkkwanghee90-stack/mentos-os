# 살아 움직이는 도형 렌더러 (단계별 빌드업 AVS 도형) — 설계

작성일: 2026-06-14
대상: mathmentos 수학교실 AVS(시각화 풀이)의 기하 도형

## 1. 목표

수학교실 AVS 해설에서, 도형이 **정적으로 한 번에 다 그려지는 것이 아니라 풀이 단계(PCBSA)를 따라 한 요소씩 쌓이며 문제를 풀어가도록** 만든다. 학생이 "원을 그리고 → 포물선을 얹고 → 교점을 찍고 → 계산" 하는 사고 흐름을 도형이 그대로 따라가게 한다.

성공 기준:
- 도형이 있는 **모든** 기하 문제가 단계별 빌드업으로 동작한다(정적·빈 도형 없음).
- 좌표·방정식이 수학적으로 정확하다(교점이 실제로 도형 위에 있음 등).
- 시각적으로 깔끔하다(흰 좌표평면 + 검정 단색).

## 2. 현재 맥락 (조사 완료)

- 렌더러는 이미 존재한다. `src/components/hints/GeometryHintPlayer.jsx` + `src/components/hints/MathCanvas.jsx`(Mafs 기반).
- **누적 렌더 메커니즘이 이미 구현됨**: `accumulatedObjects = base_figure.objects + (step 0..현재step의 objects)`. 즉 step별 `objects` 배열만 채우면 단계가 넘어갈 때마다 도형이 쌓인다. (별도 애니메이션 엔진 불필요.)
- 지원 객체 타입(MathCanvas): `axes`, `circle{center,radius}`, `function_plot{expr}`, `line/segment{from,to}`, `point{coords,label}`, `latex_label{tex,at}`, `polygon`, `triangle` 등.
- 데이터: Supabase 스토리지 `mentos-assets/math_hints/<영문단원폴더>/<pid>.json`. 앱이 런타임 fetch. 단원 폴더 매핑은 `src/config/pathMapping.js`(예: 원의방정식2단계→circle_eq_step2).
- 데이터 구조: `{ base_figure:{preset:'custom', objects:[...]}, steps:[{step,label,latex,objects?}], viewBox, ... }`. `isV3 = !!(overlay_steps || base_figure.preset==='custom')` 이면 누적 모드.
- **현재 상태**: 원의방정식 2단계 50문제 중 13개는 빌드업 적용 완료(001 손수 제작 + 도형 있던 12개 자동 분산). 나머지 ~28개는 `base_figure`가 비어 있어 도형 자체가 없다.
- 제약: 작업자(Claude)의 브라우저(Playwright) 시각검증이 현재 끊겨 있음. 좌표 수학검산은 가능.

## 3. 설계 결정

### 3.1 렌더 스타일 (코드 변경)
- 기하 캔버스 배경을 **다크 → 흰색**으로.
- 축·원·직선·점·라벨 **기본색을 검정(단색)**. 색 최소화.
- 현재 단계에서 새로 추가되는 객체만 살짝 강조(굵기/진하기), 나머지는 검정·회색.
- 변경 위치: `GeometryHintPlayer`의 `avs-canvas-col` 배경, `MathCanvas`의 기본 색상/축 색(Mafs 테마 또는 객체 color 기본값).
- 폐기: 001에서 임시로 쓴 파랑/빨강/초록.

### 3.2 데이터 패턴 (모든 도형 문제 공통, "정적 금지")
PCBSA 단계마다 도형 누적:

| 단계 | 누적되는 도형 |
|---|---|
| P 구하는 것 | 좌표축 |
| C 조건 | 주어진 도형(원/직선/포물선) 작도 |
| B 배경 | 핵심 점·보조선 |
| S 식변형 | 교점·좌표 표시 |
| A 정답 | 결과(자취/답) 강조 |

- `base_figure.objects`에는 축만 둔다(또는 비움). 나머지는 step별 `objects`로 분산.
- 단계 수가 5가 아니어도(4~13단계) 위 우선순위(도형→점→라벨)로 사용 가능한 중간 단계에 분배. 첫 단계(P)와 마지막 단계(A)는 비워 둘 수 있음.

### 3.3 작도 방법 (빈 문제)
- 각 문제의 **힌트 단계 latex에 이미 들어있는 좌표·방정식**에서 도형 객체를 생성한다(예: "(0,-2),(√3,1)", "x²+y²=4", "y=ax+b").
- 도형이 있는 문제는 기존 `base_figure.objects`를 단계별로 **분산**(자동, 무위험).
- 도형이 빈 문제는 latex에서 **신규 작도**.

### 3.4 검증
- **좌표 수학검산(자동)**: 작도한 교점이 실제 원/직선 방정식을 만족하는지, 원 중심·반지름이 방정식과 일치하는지, 점이 곡선 위에 있는지 등을 코드로 검산하여 좌표 오류를 차단.
- **단원별 라이브 스팟체크(사용자)**: 각 단원 배치 업로드 후 사용자가 라이브(`/inspector` 또는 수학교실)에서 확인.
- 작업자 브라우저 복구 시 시각검증 추가.

## 4. 분해 / 롤아웃 순서

규모가 크므로(도형 전 단원, 수백 문제) 단원별 배치 사이클로 진행한다. 각 단원 = 1 사이클(작도→좌표검산→업로드→라이브 확인).

1. **원의방정식 2단계 (파일럿, 50문제)** — 흰배경/검정 렌더 변경 + 데이터 패턴 + 작도/검산 파이프라인을 여기서 확립·검증.
2. 원의방정식 3단계
3. 원의방정식 4단계
4. 직선의방정식 2/3/4단계
5. 점과좌표 2/3/4단계
6. 도형의이동 2/3/4단계

파일럿(1단계)이 확정되면 같은 방법으로 나머지를 순차 확장.

## 5. 아키텍처 / 구성요소

- **렌더 스타일 패치** (`GeometryHintPlayer`/`MathCanvas`): 흰배경·검정 단색. 1회 코드 변경, 전 단원 공통.
- **분산기(distributor)** (스크립트): 도형이 있는 문제의 `base_figure.objects`를 단계별 `objects`로 분배. 입력=문제 JSON, 출력=빌드업 JSON. 무손실(최종 누적 = 원본).
- **작도기(authoring)**: 빈 문제의 latex → 도형 객체. 사람/서브에이전트가 수식 기반으로 작성.
- **검산기(verifier)** (스크립트): 좌표가 방정식을 만족하는지 자동 검산. 통과한 것만 업로드.
- **업로더**: Supabase 스토리지 `POST .../object/mentos-assets/math_hints/<folder>/<pid>.json` (service key, x-upsert).

각 구성요소는 독립적으로 실행·검증 가능.

## 6. 데이터 흐름

문제 JSON(스토리지) → [분산기 or 작도기] → 빌드업 JSON → [검산기: 좌표·JSON 유효성] → 업로더 → 스토리지 덮어쓰기 → 앱 런타임 fetch → 단계별 누적 렌더.

## 7. 에러 처리 / 검증

- 검산 실패(교점이 도형 위에 없음, JSON 오류, 객체 누락) 시 업로드 보류 + 리스트업.
- 분산기는 무손실(최종 도형 = 원본)이라 도형 있는 문제는 안전.
- 작도기 결과는 좌표검산 필수 통과 후 업로드.
- 단원별 업로드 후 사용자 라이브 확인을 게이트로 둠.

## 8. 범위 밖 (YAGNI)

- 연속 모션 애니메이션(점이 곡선을 따라 부드럽게 이동 등) — 이번엔 "단계별 누적 등장"까지만. 추후 별도.
- 새 객체 타입 추가 — 기존 MathCanvas 타입으로 충분.
- 도형 외 단원(대수)의 AVS — 대상 아님.
- TTS 재생성 — 무관.

## 9. 미해결 / 가정

- 흰배경/검정 렌더 변경이 기존 다크 테마 칠판 UI와 시각적으로 충돌하지 않는지 — 파일럿에서 라이브 확인.
- 일부 문제는 latex에 좌표가 충분치 않을 수 있음 — 그런 경우 해당 문제는 최소 도형(주어진 원/직선)만 작도하고 리스트업.
