# 난이도 상향 대량화 러너 — 설계 (Design Spec)

- **작성일**: 2026-06-18
- **상태**: 승인됨(구현 계획 단계로 진행)
- **연관 메모리**: exam-predict-pipeline

## 1. 배경 / 문제

학교별 기말 **예상문제**(고1 공통수학1 81교 + 고2 수학Ⅰ 53교, 학교당 20문항×3회차)를 이미 생성했으나, 3개교(가락·휘문·진주) 무작위 검수 결과 **원본 기출보다 현저히 쉬움**이 확인됨:

- 원본 킬러의 **다단계·결합·역추론·경우분리** 장치를 "공식 1~2번 적용 단답"으로 치환
- **'심화' 라벨 인플레이션**(이름만 심화, 실제는 ★2~3)
- 일부 풀이 논리 오류

이를 학교당 고품질 에이전트로 **원본 raw_png 기준 킬러급 재생성**하면 해결되나(검증됨: 19교 완료), 학교당 100~200k 토큰으로 **세션/주간 한도에 반복적으로 막혀** 수동 재개가 필요하다. 남은 **미게시 ~109교**를 한도에 막히지 않고 전수 상향하는 **자동 재개형 파이프라인**이 필요하다.

## 2. 목표 / 비목표

**목표**
- 미게시 ~109교(고1 강남·분당 우선 → 나머지 고1 → 고2 남은분)를 **원본 킬러급**으로 전수 난이도 상향
- 세션/주간 한도에 막혀도 **자동으로 자고 이어서** 무인 진행(/loop)
- 학교마다 **생성→검수 게이트**로 "아직 쉬움"을 차단(드리프트 방지)
- 배치마다 안전 커밋, 주기적으로 앱 배포

**비목표(YAGNI)**
- 게시된 12교 재상향(앱 일부는 이미 상향됨, 네이버 재업로드는 별도 수동 트랙)
- 생성 방식 자체 변경(템플릿 라이브러리·모델 다운 등) — **현재 고품질 에이전트 방식 유지**
- 블로그 자동 게시·자체블로그 구축(별도 트랙)

## 3. 결정 사항 (확정)

| 항목 | 결정 |
|---|---|
| 생성 방식 | 현재 학교당 고품질 에이전트(raw_png 정독 → 카드 전면 재생성) 유지 |
| 자동 재개 | **/loop 셀프페이싱**(ScheduleWakeup): 가능하면 다음 배치, 한도면 길게 자고 재시도 |
| 검수 | **전수 검수 에이전트 게이트**(생성→검수→미달 시 재큐) |
| 대상 범위 | **미게시만**(게시 12교 제외) ≈ 109교 |
| 순서 | 고1 강남·분당 우선 → 나머지 고1(지역순) → 고2 남은분 |
| 배치 크기 | **5교/배치** |
| 배포 주기 | **3배치(≈15교)마다** + 큐 소진 시 |

## 4. 아키텍처 / 구성요소

모든 산출물은 `scripts/blog_auto/`. 러너는 **한 /loop 턴 = 한 배치**로 동작한다.

### 4.1 트래커 — `difficulty_progress.json`
파이프라인의 **단일 진실원**. 학교별 상태:
- `done` — 상향+검수 통과
- `deferred` — 한도로 미처리(실패 아님, 다음 턴 재시도)
- `needs_review` — 검수 2회 연속 '쉬움'(사람 개입 필요, 큐에서 제외)
- `needs_source` — raw_png 없음(skip)

스키마: `{ done:[{grade,slug}], deferred:[...], needs_review:[...], needs_source:[...], posted_excluded:[...] }`.

### 4.2 선택기 — `next_pick.cjs`
입력: 트래커 + 두 번들 + 게시12교 목록.
출력: **다음 N개(기본 5)** `{grade,slug,region}` — `done ∪ needs_review ∪ needs_source ∪ posted` 제외, **강남·서초·송파·분당·성남 우선 → 그 외 지역 가나다순**. 고1 소진 후 go2. 큐가 비면 빈 배열(러너 종료 신호).

### 4.3 배치 러너 (한 턴)
1. 선택기로 다음 5개. 빈 배열이면 **종료**(최종 배포 후 /loop 중단).
2. **생성**: 5개 생성 에이전트 병렬(검증된 고품질 프롬프트 — raw_png 정독 → `cards/predicted/analysis` 덮어쓰기, 60문항 자가검산, KaTeX 엄수, '심화' 정직 라벨).
3. **검수**: 생성 성공분만 5개 검수 에이전트 병렬(원본 raw_png vs 새 카드 1:1, 판정 `적정 / 쉬움` + 근거·가장 쉬운 문항).
4. **판정 반영**:
   - `적정` → 트래커 `done`.
   - `쉬움` → 검수 근거를 프롬프트에 붙여 **1회 재생성→재검수**. 2회째도 `쉬움` → `needs_review`.
   - 생성/검수가 한도·치명 에러로 실패 → `deferred`.
5. **안전 커밋**: 이 배치에서 `done`된 학교의 `cards/predicted/analysis` + 트래커 커밋·푸시.

### 4.4 주기 배포
배치 카운터가 3의 배수이거나 큐 소진 시:
- `06_bundle.cjs`(go1) + `EXAM_OUT_BASE=…go2 06_bundle.cjs`(go2) 재빌드
- `build_hero_showcase.cjs` 재생성
- `rm -rf dist && npm run build && npm run deploy` → 라이브 청크 일치 검증
- 상향 학교 분석/예상문제 포스터 재렌더(`02_render`·`04_render_problems`) → SMB

### 4.5 /loop 셀프페이싱
- 작업 가능(직전 턴 한도 신호 없음) → 다음 배치 즉시 진행, 다음 깨움 ~270s
- 한도 신호 감지(에이전트 "session/weekly limit") → ScheduleWakeup **1200~3600s**(리셋 시각 고려)
- 큐 비면 ScheduleWakeup 생략 → 루프 종료

## 5. 데이터 흐름

```
선택기(트래커+번들) → [생성 에이전트 ×5] raw_png→카드 덮어쓰기
   → [검수 에이전트 ×5] raw_png vs 카드 (적정/쉬움)
   → 트래커 갱신(done/needs_review/deferred) → 배치 커밋
   → (3배치마다) 번들 재빌드 → 빌드 → 배포 → 포스터 재렌더
   → /loop: 한도면 길게 자고 재시도, 큐 비면 종료
```

## 6. 실패 / 엣지 처리

- **한도(세션/주간)**: `deferred`로 두고 길게 자기 — 토큰 소진하지 않음. 리셋 후 재시도.
- **raw_png 없음**: `needs_source` 마킹·skip(원본 없이는 난이도 패리티 불가).
- **검수 2회 연속 '쉬움'**: `needs_review`로 큐에서 빼 **진행 막힘(head-of-line block) 방지**.
- **KaTeX/정답 깨짐**: 생성 자가검산(1차) + 검수(2차) 이중 차단.
- **동명이교(go1/go2 낙동·화명·구암 등)**: 트래커·파일이 `(grade,slug)`로 구분되므로 충돌 없음.
- **번들 오염**(개별 에이전트가 번들 건드림): 에이전트는 번들 미수정 원칙, 러너가 4.4에서 **클린 재빌드**로 권위 복구.

## 7. 성공 기준 (Acceptance)

- 미게시 ~109교 전부 `done`(또는 명시적 `needs_review`/`needs_source`)으로 종결.
- `done` 학교: 검수 판정 `적정`, 심화 비율·서술형 수 원본 동급, 60문항 자가검산 통과, KaTeX 깨짐 0.
- 무인 운영 중 한도로 인한 **데이터 손상·중복 0**, 수동 개입은 `needs_review`에 한정.
- 상향분이 앱(라이브)·QR 펀넬에 반영.

## 8. 테스트 / 검증

- **러너 단위**: 선택기가 done/posted 제외하고 우선순위대로 N개 반환(고정 입력 → 기대 출력).
- **트래커 멱등성**: 같은 학교 두 번 done 처리해도 중복 없음.
- **게이트 동작**: '쉬움' 판정 → 재큐 1회 → 2회째 `needs_review` 전이.
- **통합(드라이런)**: 1배치(5교)를 끝까지 돌려 done·커밋·(배포 스킵) 확인 후 전체 가동.
- **회귀**: 이미 `done`된 19교는 재처리하지 않음(선택기 제외 확인).

## 9. 미해결 / 후속

- 게시 12교의 네이버 글 재업로드(상향 포스터 재생성→사람 업로드) — 별도 트랙.
- 검수 에이전트의 '적정/쉬움' 판정 기준 캘리브레이션(최초 몇 배치 사람 샘플 대조로 보정).
